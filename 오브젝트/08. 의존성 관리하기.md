## 컨텍스트 독립성
클래스가 자신과 협력할 구체적인 클래스를 알면 알수록 그 클래스가 사용되는 문맥에 강하게 결합된다. 

- 어디서 어떻게 사용될지 너무 많이 알고 있으면 재사용이어렵다.
- 어디서 사용될지 잘 모르는 상태에서도 잘 동작하는 구조를 컨텍스트 독립성이라 한다. 


## 바람직한 의존성
- 바람직하지 않은 의존성: 다른 환경에서 사용할 때, 내부 구현을 변경해야 하는 구조
- 바람직한 의존성: 컨텍스트에 독립적인 의존성, 다양한 환경에서 재사용 가능

  
#### 의존성 해결 방식 3가지
1. 생성자 주입
2. setter 주입
3. 메서드 인자 주입
-> 외부에서 객체를 주입받는 방식으로 직접 생성하지 않는다.



#### 명시적인 의존성
퍼블릭 인터페이스를 통해 설정을 유동적으로 할 수 있는지 방법을 제공하는지

- 명시적인 의존성: 의존성이 명시적으로 퍼블릭 인터페이스에 노출되는 경우
- 숨겨진 의존성: 의존성이 퍼블릭 인터페이스에 표현되지 않는 경우


-> 의존성을 외부에서 주입하라

####  new는 해롭다
- 구체적인 클래스에 직접 의존
- 생성자의 파라미터를 알아야 한다.



### 유연하고 재사용 가능한 설계
- 컨텍스트에 독립적이며 명시적인 의존성을 갖는 설계
- 결합도가 낮고, 추상화에 의존하는 구조
