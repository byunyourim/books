### 컨텍스트 독립성
어떤 문맥(Context)에서도 잘 동작할 수 있는 코드 구조

- 클래스가 자신과 협력할 구체적인 클래스를 알면 알수록 그 클래스가 사용되는 문맥에 강하게 결합된다. 
- 어디서 어떻게 사용될지 너무 많이 알고 있으면 재사용이어렵다.
- 어디서 사용될지 잘 모르는 상태에서도 잘 동작하는 구조를 컨텍스트 독립성이라 한다. 

---
### 바람직한 의존성
#### 바람직하지 않은 의존성
- 특정 환경에 강하게 묶여 있음
- 내부 구현 변경 시 외부 코드 영향
- 재사용 어렵고 유지보수 힘듦
#### 바람직한 의존성
- 컨텍스트(환경)에 독립적
- 다양한 환경에서 재사용 가능
- 내부 변경에 유연함

---
### 의존성 해결 방식 3가지
1. 생성자 주입
2. setter 주입
3. 메서드 인자 주입
- 특정 동작에 필요한 의존성을 메서드 호출 시 외부에서 전달
- 외부에서 객체를 주입받는 방식으로 직접 생성하지 않는다.

---
### 명시적인 의존성 vs 숨겨진 의존성
퍼블릭 인터페이스를 통해 설정을 유동적으로 할 수 있는지 방법을 제공하는지

#### 명시적인 의존성
- 의존성이 명시적으로 퍼블릭 인터페이스에 노출되는 경우
- 사용자가 어떤 객체가 필요한지 쉽게 알 수 있음
#### 숨겨진 의존성
- 의존성이 퍼블릭 인터페이스에 표현되지 않는 경우
- 내부에서 new 등으로 직접 생성
- 외부에서 인식 불가, 유지보수 어려움


-> 의존성을 외부에서 주입하라

---
###  new는 해롭다
- 구체 클래스에 직접 의존 → 결합도 증가
- 생성자 인자를 외워야 함 → 복잡성 증가
- 유연성 부족, 테스트 어려움


<br>

### 좋은 설계?
- 외부에서 의존성 주입 (DI)
- 컨텍스트에 독립적이며 명시적인 의존성을 갖는 설계
- 결합도가 낮고, 추상화에 의존하는 구조
