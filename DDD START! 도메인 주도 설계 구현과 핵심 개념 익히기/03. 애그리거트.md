# 애그리거트
도메인 모델 중 서로 강하게 연결된 것들을 하나로 묶은 단위  
   
- 일관성을 함께 유지해야하는 객체들의 묶음
- 애그리거트 루트가 존재함
- 트랜잭션 경계 = 애그리거트 경계

-> 도메인 모델 안에서 일관성을 유지해야하는 단위


예)
- 도메인 - 온라인 서점
- 하위 도메인 - 주문, 결제, 배송, 리뷰 등
- 애그리거트 - 주문 (order, orderItem, shippingInfo), 결제 (paymenet)


<br>

---

## 애그리거트 루트
애그리거트는 여러 객체로 구성되기 때문에 한 객체만 상태가 정상이면 안됨.  
도메인 규칙을 지키기 위해서는 애그리거트에 속한 모든 객체가 정상이어야 함.  

애그리거트에 속한 모든 객체가 일관성을 유지하려면 애그리거트 전체를 관리할 주체가 필요한덷,
해당 책임을 지는 것이 바로 애그리거트의 루트 엔티티이다.  

애그리거트에 속한 객체는 애그리거트 루트 엔티티에 직접, 간접적으로 속한다.


<br>

## 도메인 규칙과 일관성
애그리거트 루트의 핵심은 애그리거트의 일관성이 깨지지 않도록 하는 것이다. 
그래서 애그리거트 루트는 애그리거트가 제공해야 할 도메인 기능을 구현한 메서드를 제공한다.  
   
**애그리거트 루트를 통해서만** 상태를 바꿀 수 있도록 해야 한다. 




<br>

## 트랜잭션 범위
트랜잭션 범위는 작을수록 좋다. 

하나의 테이블을 수정하면 트랜잭션 충돌을 막기 위해 잠그는 대상이 한 개 테이블의 한 행으로 한정되지만,
세 개의 테이블을 수정하면 잠금 대상이 많아진다. 
   
잠금 대상이 많아지면 그만큼 동시에 처리할 수 있는 트랜잭션의 갯수가 줄어든다. -> 전체 성능 저하





<br>

## 레포지토리와 애그리거트
레포지토리는 애그리거트 단위로 존재함.
Order 와 OrderLine 이 각각 다른 테이블에 있어도 레포지토리는 Order 하나만 존재함.

-> OrderLine은 Order 애그리거트의 내부 구성요소이기 때문에 외부에서는 항상 Order을 통해서만 접근해야 한다.




<br>

## ID를 이용한 애그리거트 참조
한 애그리거트가 다른 애그리거트를 참조할 때는 ID로만 참조한다. 

-> 객체로 직접 참조하게되면 강하게 연결되어 결합도가 높아진다. 
-> 아이디로 연결하면 느슨하게 연결되고, 독립성이 보장됨.
