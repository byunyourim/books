#### 함수 객체로 사용
```java
Collections.sort(words, new Comparator<String>() {
	public int compare(String s1, String s2) {
		return Integer.compare(s1.length(), s2.length());
	}
});
```
---

### 람다
```java
Collections.sort(words, (s1, s2) -> Integer.compare(s1.length(), s2.length()));
```
자바 8부터 도입된 함수형 프로그래밍 기법으로, 함수형 인터페이스의 인스턴스를 간결한게 표현하도록 도와준다.
람다를 사용하면 컴파일러가 대신 인터페이스에 대한 타입추론을 해주기 때문에, 타입을 생략할 수 있다.

**함수형 인터페이스**  
추상 메서드를 하나만 가진 인터페이스  

람다를 사용하면 코드의 가독성이 높아지고, 익명 클래스를 대체할 수 있다. 
타입 추론을 통해 매개변수와 반환 타입을 자동으로 추론하며, 제네릭을 활용해 더 명확한 타입 정보를 제공할 수 있다.  


---

### 람다와 익명 클래스
- 람다는 함수 객체를 간결하게 구현할 수 있지만, 자신을 참조할 수 없다. 람다의 this는 바깥 인스턴스를 가리키며, 이름이 없고
문서화가 불가능하다. 줄 수가 많아지면 가독성이 떨어지기 때문에 사용하지 말자.


- 익명 클래스는 타입의 인스턴스를 만들 때만 사용하자. 함수 객체가 자신을 참조해야 할 경우에도 익명 클래스를 사용하자.  
  
- 람다와 익명 클래스 모두 직렬화가 구현별로 다를 수 있다. 따라서 직렬화를 삼가하고, 필요하다면 private 중첩 클래스를 사용하자
