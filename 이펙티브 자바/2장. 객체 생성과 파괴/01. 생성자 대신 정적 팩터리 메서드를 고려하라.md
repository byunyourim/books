- **public** 생성자
  ```java
  public class Person {
      public Person() {};
  }
  ```
- **정적 팩터리 메서드**
    ```java
    public class Person {
        private String name;
        private int age;
    
        private Person(String name, int age) {
            this.name = name;
            this.age = age;
        }
    
        // 정적 팩토리 메서드: 사용자 지정 나이로 인스턴스 생성
        public static Person createWithCustomAge(String name, int age) {
            return new Person(name, age);
        }
    }
    ```

## 정적 팩터리 메서드의 특징 및 장단점
static로 선언된 메서드로, new Object() 처럼 객체를 생성하지 않고 사용할 수 있는 메서드이다.  


### 장점
#### 1. 이름을 갖는다.

하나의 클랫스에 생성자가 여러 개 필요한 경우, 정적 팩터리 메서듣를 이용해서 다양하게 이름을 붙여줄 수 있다.
이름을 통해 반환될 객체의 특성을 묘사할 수 있다. 
하나의 객체의 생성자를 매개 변수만 다르게 해서 오버로딩하면 해당 생성자가 반환하는 객체의 특성을 제대로 설명하지 못하기 때문에 의미를 알기 어렵다.
```java
public class Person {
    public Person(String name) { }   
    public Person(int id) { }
}
```
하지만 정적 팩터리 메서드를 사용하면 의미를 명확하게 할 수 있다. 
```java
public class Person {
    public createByName(String name) {
      Person person = new Person();
      person.name = name;
      return person;
    }   
    public createById(int id) {
      Person person = new Person();
      person.id = id;
      return person;
    }
}
```

#### 2. 호출될 때마다 인스턴스를 새로 생성하지 않아도 된다.
매번 새로운 객체를 생성하는 대신 이미 존재하는 객체를 재사용할 수 있다.
```java
public static Boolean valueOf(boolean b) {
    return b ? Boolean.TRUE : Boolean.FALSE;
}
```
자바에서 Boolean 클래스는 valueOf라는 정적 팩터리 메서드를 갖는다. 새로운 객체를 생성하지 않고 이미 만들어진 Boolean.TRUE, Boolean.FALSE 객체를 반환한다. 
따라서, Boolean.valueOf(true)를 여러 번 호출해도 항상 같은 Boolean.True 객체를 반환한다.
이렇게 하면 Boolean 객체를 매번 새로 생성하는 비용을 줄이고 메모리를 절약할 수 있다.



```java
// Integer.valueOf()
public static Integer valueOf(int i) {
    if (i >= -128 && i <= 127) { // 캐시 범위 확인
        return IntegerCache.cache[i + 128];
    }
    return new Integer(i); // 캐시에 없으면 새 객체 생성
}
```

Integer의 valueOf 메서드는 -128에서 127 사이의 정수 값에 대해서는 캐싱된 인스턴스를 반환하여 작은 정수 범위의 인스턴스를 계속 재사용하기 때문에, 불필요한 메모리 사용을 줄일 수 있다.

```java
public class Person {
    private String t;
    private int age;

    private static final Person ADULT = new Person("성인", 18);

    private Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public static Person getAdultInstance() {
        return ADULT;  // 항상 같은 ADULT 객체 반환
    }
}
```
Person.getAdultInstance()를 호출할 때마다 새로운 객체를 만들지 않고, 미리 만들어둔 ADULT 객체를 재사용한다.



- 특정 조건에서 객체를 재사용하게 만들거나, 아예 한 번만 생성된 객체를 반환하는 싱글톤 패턴을 구현할 수 있다.
```java
class Singleton {
    private static Singleton singleton = null;

    // 생성자를 private 으로 선언하여 new 키워드를 통한 객체 생성을 막는다.
    private Singleton() {}

    // 인스턴스가 없으면 생성, 있으면 반환
    static Singleton getInstance() {
        if (singleton == null) {
            singleton = new Singleton();
        }
        return singleton;
    }
}
```
  
- 필요한 경우 새로운 객체를 반환할 수도 있지만, 재사용이 가능할 때는 기존 객체를 반환할 수 있다. (유연성)
생성 비용이 큰 같은 객체가 자주 요청 되는 경우 성능을 높일 수 있다.

> 
<details>
  <summary><b>플라이웨이트 패턴 Flyweight Pattern</b></summary>
객체를 가능한 공유해서 메모리 사용을 줄이는 패턴으로 객체가 많아질수록 메모리 사용량이 커지는 문제를 해결하기 위해서 고안됨
  
#### 플라이웨이트 패턴의 구성 요소
- 플라이웨이트 인터페이스(Flyweight Interface): 공통으로 사용하는 메서드
- 콘크리트 플라이웨이트(Concrete Flyweight): 실제로 공유되는 객체를 정의하며, 외부 상태와 구분되는 내부 상태를 갖는다.
- 플라이웨이트 팩토리(Flyweight Factory): 플라이웨이트 객체를 생성하고 관리하며, 이미 생성된 객체가 있으면 기존 객체를 반환하고, 없으면 새로 생성하여 공유한다.
- 내부 상태와 외부 상태:
내부 상태는 객체가 공유할 수 있는 불변의 속성, 외부 상태는 객체가 독립적으로 가질 수 있는 가변적인 속성으로, 호출 시 외부에서 전달된다.

```java
// Flyweight 인터페이스
interface Glyph {
    void display(int positionX, int positionY);  // 외부 상태인 위치를 전달받음
}

// Concrete Flyweight 클래스
class Character implements Glyph {
    private final char symbol;  // 내부 상태: 공유되는 불변의 속성인 문자

    public Character(char symbol) {
        this.symbol = symbol;
    }

    @Override
    public void display(int positionX, int positionY) {
        System.out.println("Character: " + symbol + " at (" + positionX + ", " + positionY + ")");
    }
}

// Flyweight Factory 클래스
class CharacterFactory {
    private final Map<Character, Glyph> characters = new HashMap<>();

    public Glyph getCharacter(char symbol) {
        Glyph character = characters.get(symbol);
        
        if (character == null) {
            character = new Character(symbol);  // 객체가 없으면 생성
            characters.put(symbol, character);  // 캐시에 저장
        }
        
        return character;  // 이미 있으면 기존 객체 반환
    }
}

// 클라이언트 코드
public class FlyweightExample {
    public static void main(String[] args) {
        CharacterFactory factory = new CharacterFactory();

        Glyph a1 = factory.getCharacter('a');  // 새로운 'a' 생성
        Glyph a2 = factory.getCharacter('a');  // 기존의 'a' 반환 (재사용)
        Glyph b1 = factory.getCharacter('b');  // 새로운 'b' 생성

        a1.display(10, 20);
        a2.display(15, 25);
        b1.display(30, 35);

        System.out.println("a1과 a2는 같은 객체? " + (a1 == a2));  // true 출력
    }
}
```
CharacterFactory는 객체를 캐시에 저장해, 동일한 문자 요청이 들어오면 이미 생성된 객체를 반환한다.
a1과 a2는 같은 문자 ‘a’를 참조하기 때문에 a1 == a2는 true이다.
display() 메서드는 외부 상태인 위치 값을 전달받아 표시한다.

#### 장점
- 메모리 절약: 공유 가능한 객체를 재사용하므로 메모리 사용량을 줄일 수 있습니다.
- 성능 향상: 메모리를 절약해 프로그램이 더 효율적으로 실행될 수 있습니다.
#### 단점
- 구현 복잡도 증가: 외부 상태와 내부 상태를 분리해야 해서 코드가 복잡해질 수 있습니다.
- 객체 관리의 어려움: 공유되는 객체와 독립적인 객체의 관리가 복잡할 수 있습니다.

### 정적 팩터리 메서드 명명 방식
- from
  매개변수를 하나 받아서 해당 타입의 인스턴스를 반환하는 형 변환 메서드
  ```java
  Date d = Date.from(instant);
  ```
  
- of
  여러 매개변수를 받아 적합한 타입의 인스턴스를 반환하는 집계 메서드
  ```java
  Set<Rank> faceCards = EnumSet.of(JACK, QUEEN, KING);
  ```

- valueOf
  from과 of의 더 자세한 버전
  ```java
  BigInteger prime = BigInteger.valueOf(Integer.MAX_VALUE);
  ```
  
- instance or getInstance
  매개변수로 명시한 인스턴스를 반환하지만, 같은 인스턴스임을 보장하지 않는다.
  ```java
  StackWalker luke = StackWalker.getInstance(options);
  ```

- create or newInstance
  instance, getInstance와 같지만, 매번 새로운 인스턴스를 생성해 반환함을 보장한다.
  ```java
  Object newArray = Array.newInstance(classObject, arrayLen);
  ```
  
- getType
  getInstance와 같으나, 생성할 클래스가 아닌 다른 클래스에 팩터리 메서드를 정의할 때 사용한다. Type은 팩터리 메서드가 반환할 객체의 타입이다.
  ```java
  FileStore fs = Files.getStore(path);
  ```

- newType
  newInstance와 같으나 생성할 클래스가 아닌 다른 클래스의 팩터리 메서드를 정의할 때 쓴다. Type은 팩터리 메서드가 반환할 객체의 타입이다.
  ```java
  BufferedReader br = Files.newBufferedReader(path);
  ```
  
- type
  getType과 newType의 간결한 버전
  ```java
  List<Complaint> litany = Collections.list(legacyLitany);
  ```
