## 타입 이종 컨테이너
타입이 다른 원소를 타입 안전하게 담는 컨테이너 제네릭 타입 시스템을 활용해 타입안정성을 제공한다.   

일반적으로 제네릭 컬렉션은 같은 타입의 객체를 다루지만, 이종 컨테이너는 다양한 타입을 동시에 다룰 수 있다.  

키를 타입으로 매핑하여 객체를 관리한다. 키가 컨테이너에 저장될 값의 타입을 결정하고, 이를 통해 컴파일 타임에 타입을 검증할 수 있다.  

---
#### 구현
1. 컨테이너 대신 키를 매개변수화
2. 컨테이너에 값을 넣거나 뺄 때 매개변수화한 키를 함께 제공한다.

```java
public class Favorites {

    private Map<Class<?>, Object> favorites = new HashMap<>();
    
    public <T> void putFavorites(Class<T> type, T instance) {
    	favorites.put(type, instance);
    }
    
    @SuppressWarnings("unchecked")
    public <T> T getFavorites(Class<T> type) {
    	return (T) favorites.get(type);
    }
}
```
```java
public class Main {
	
    public static void main(String[] args) {
        
        Favorites favorites = new Favorites();
        favorites.putFavorites(Integer.class, 1);
        int integer = favorites.getFavorites(Integer.class);
        favorites.putFavorites(String.class, "가나다");
        System.out.println("Integer.class : " + integer);
        System.out.println("String.class : " + favorites.getFavorites(String.class));
        
        
    }

}
```
```java
private Map<Class<?>, Object> favorites = new HashMap<>() ;
```

`Map<Class<?>, Object>`는 모든 클래스를 키로 사용할 수 있지만, 키와 값의 타입 관계를 보장하지 못한다.  

즉, 키가 String.class라면 값이 반드시 String 타입이어야 하는 걸 컴파일러가 확인할 수 없다. 

그래서 타입 안전성을 확보하려면 다른 방법을 써야 함.





컴파일러가 타입 검증을 수행하기 때문에 런타임에 오류를 방지할 수 있고, 서로 다른 타입의 객체를 같은 컨테이너에서 다룰 수 있다. 
또한 타입을 명시적으로 저장하기 때문에 코드의 가독성이 향상된다.  

---
#### 예제
- Class 객체를 키로 사용하는 이종 컨테이너
- 명확한 타입 제약이 필요한 경우, 같은 데이터 구조에서 다양한 타입의 값을 다루어야 할 때


타입 안전을 위해 키와 값의 타입을 정확히 매칭해야 하며, 동작을 보장하기 위해서는 
키 객체의 불변성과 올바른 equals, hashCode 구현이 중요하다.
