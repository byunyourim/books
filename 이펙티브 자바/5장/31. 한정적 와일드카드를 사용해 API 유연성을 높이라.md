불공변 : 하위 타입이 상위 타입으로 대체될 수 없다는 것을 의미한다. 
즉, 제네릭 타입 매개변수가 서로 다른 타입일 경우, 컴파일 에러가 발생한다. 따라서 타입 안정성을 보장하지만
API 유연성이 제한된다.  



---

### 와일드 카드의 필요성
제네릭 메서드, 제네릭 클래스를 설계할 때, 유연성을 높이기 위해 와일드 카드를 사용해야 할 때가 많다.
와일드카드를 사용하면 호출자가 의도에 맞게 다양한 타입을 전달할 수 있다.



### 문제와 해결
- 한정적 와일드 카드


유연성을 극대화하려면 원소의 생사자나 소비자용 입력 매개변수에 와일드카드 타입을 사용하자.    


한편, 입력 매개변수가 생산자와 소비자 역할을 동시에 한다면 다른 방법을 사용하자.  
타입을 정확히 지정해야 할 때는 와일드카드 타입을 쓰지 말아야 한다.

## 제네릭에서의 생산자와 소비자

```java
// E 생산자(producer) 매개변수에 와일드카드 타입 적용
public void pushAll(Iterable<? extends E> src) {
	for (E e : src) push(e);
}


// E 소비자(consumer) 매개변수에 와일드카드 타입 적용
public void popAll(Collection(? super E) dst) {
	while (!isEmpty()) dst.add(pop());
}
```

### PECS, producer-extends, consumer-super
- `<? extends T>` : 데이터를 생산하는 경우 사용하며 하위 타입을 읽을 수 있지만, 데이터 추가는 안됨
- `<? super T>` : 데이터를 소비하는 경우 사용하며, 그 상위 타입에 데이터를 추가할 수 있자만, 읽을 때는 Object 타입으로 취급됨

```java
public double sum(List<? extends Number> numbers) {
    double sum = 0.0;
    for (Number number : numbers) {
        sum += number.doubleValue();
    }
    return sum;
}
```

```java
public void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
}
```
