
```java
class Point {
    public double x;
    public double y;
}
```
위와 같이 인스턴스 필드들을 모아놓는 일 외에는 아무 목적도 없는 퇴보한 클래스를 작성 할 때가 있다.


#### 문제가 뭘까?
- API를 수정하지 않고는 내부 표현을 바꿀 수 없다.
  - 클래스 내부 구조(필드나 로직)가 외부에 드러나 있으면, 내부를 변경할 때 외부 코드도 고쳐야 한다
- 불변식을 보장할 수 없다.
- 외부에서 필드에 접근할 때 부수 작업을 수행할 수 없다. 




<br><br><br><br><br><br><br>





철저한 객체지향 프로그래머는 이런 클래스를 상당히 싫어해서
이러한 필드들 모두 private으로 바꾸고 public 접근자(getter)를 추가한다.  

```java
class Point {
    private double x;
    private double y;
    
    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }
    
    public double getX() {
        return x;
    }
    
    public double getY() {
        return y;
    }
    
    public void setX() {
        this.x = x;
    }
    
    public void setY() {
        this.y = y;
    }
}
```
패키지 외부에서 접근할 수 있는 클래스라면 public 접근자를 제공하여 유연성을 얻을 수 있다. 

public 클랫스가 필드를 공개하면 이를 사용하는 클라이언트가 생길 것이므로, 내부 표현 방식을 바꿀 수 없게된다.

- getter/setter 메서드를 통해 언제든지 내부 표현을 바꿀 수 있으며, 불변식이 보장된다.
- 클라이언트는 메서드를 통해서만 필드에 접근 가능하고, 외부에서 필드에 접근할 때 부수 작업을 수행 시킬 수 있다.
- getter/setter 메서드에 얼마든지 추가 가능하다.



<br><br><br><br><br><br><br>

## package-private 클래스, private 중첩 클래스
package-private 클래스, private 중첩 클래스 라면 데이터 필드를 노출해도 문제가 없다.

## public 클래스의 필드를 직접 노출시킨 사례
대표적으로 java.awt.package 의 Point와 Dimension이 있다. 
<img width="1095" alt="image" src="https://github.com/user-attachments/assets/86a74f7c-635b-4c2c-a2e9-3c184e644429">

내부를 노출한 Dimension은 오늘날까지 성능 문제를 해결하지 못했다....  


final을 이용해서 불변하도록 한다면 좀 낫나?
단점은 좀 줄지만 좋지 않다.  
**왜?** API를 변경하지 않고는 표현 방식을 바꿀 수 없고, 필드를 읽을 때 추가 작업을 할 수 없다. 
예로, 시간을 24시간제로 저장하는 대신 12시간제로 저장하고 싶다면, API에서 변경해야 한다. 
getHour() 메서드에서 반환 값이 12시간제로 나오도록 로직을 수정해야 한다.

하지만 불변은 보장할 수 있다.
```java
public final class Time {
    public final int hour;
    public final int minute;

    public Time(int hour, int minute) {
        this.hour = hour;
        this.minute = minute;
    }
```




<br><br><br><br><br><br><br>


### 마무리 
public 클래스는 절대 가변 필드를 직접 노출해서는 안 되며, 불변 필드여도 노출해서 좋을게 없다.    
단, package-private 클래스나 private 중첩 클래스를 통해서 필드를 노출하는 것이 나을 때도 있다.
