### 추상 클래스와 인터페이스 차이?
#### 추상 클래스
- 키워드 : extends (확장하다)
- 추상클래스를 구현한 클래스는 반드시 추상 클래스의 하위 클래스가 된다.
- 자바는 단일 상속을 지원하기 때문에 이 방식을 사용할 경우 새로운 타입을 정의하는데 큰 제약이 생긴다.

#### 왜 다중 상속 안돼?
==> **다이아몬드 문제 때문**
```java
abstract class A {
    abstract void methodA();
    void commonMethod() {
        System.out.println("Common from A");
    }
}

abstract class B {
    abstract void methodB();
    void commonMethod() {
        System.out.println("Common from B");
    }
}

// 다중 상속 허용 시...
// class C extends A, B {} // 컴파일 에러
// C가 commonMethod()를 호출할 때, A의 메서드를 사용할지 B의 메서드를 사용할지 알 수 없다.
```

#### 다이아몬드 문제란 무엇인가?
하나의 클래스가 두 개 이상의 클래스를 상속 받을 때, 두 부모 클래스에서 같은 이름의 메서드를 상속받게 되면 호출 시 어떤 메소드를 호출해야 할 지 모른다. 

이 구조가 다이아몬드 형태와 같아서 다이아몬드 문제라 한다.

자바는 이러한 다이아몬드 문제를 방지하기 위해 다중 상속을 지원하지 않는다. 하지만 인터페이스를 통해 상속과 유사한 동작할 수 있다.
**왜냐하면 인터페이스는 구현이 없기 때문에 다이아몬드 문제가 생기지 않는다.!!!**


```java
interface flyable {

    public void fly();

    public void move();
}


interface walkable {

    public void walk();

    public void move();
}



class Bird implements flyable, walkable{

    @Override
    public void fly() {
    }

    @Override
    public void walk() {
    }

    @Override
    public void move() {
    }
}
```


하지만, 자바 8 이후로, 인터페이스에 default메소드의 추가가 가능해지면서 다이아몬드 문제가 나타났다. 왜냐 디폴트메소드를 통해 인터페이스에도 구현 코드를 포함시킬 수 있게 되었기 때문이다.

**==> 방지하기 위해 명확한 규칙을 제공함**
동일한 디폴트 메소드를 갖는 여러 인터페이스를 상속 받는 클래스는 해당 메소드를 오버라이드해서 구현해야 한다.









<br>

#### 인터페이스
- keyword : implements (구현하다)
- 인터페이스를 구현한 클래스는 다른 어떤 클래스를 상속했던 같은 타입으로 취급된다.
- 2개 이상의 인터페이스 모두 구현해도 문제 없다.
- 자바 8이후 인터페이스의 디폴트 메서드를 사용하여 구현을 명확하게 할 수 있다.



#### 인터페이스의 default 메서드?
디촐트 메서드는 equals와 hashcode를 디폴트 메서드로 제공하지 않는닫.
디폴트 메서드를 제공할 때는 @implSpec를 이용해 설명을 문서화해야 한다.
디폴트 메서드는 인스턴스 필드를 가질 수 없고, private 정적 메서드를 가질 수 없다. 
본인이 만든 인터페이스가 아니면 디폴트 메서드를 추가할 수 없다.
