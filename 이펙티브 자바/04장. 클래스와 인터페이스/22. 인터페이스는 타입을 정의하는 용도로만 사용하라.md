**인터페이스는 타입의 역할을 한다?**   

"타입"은 객체의 종류나 형식으로 String, Integer와 같은 것이 객체의 타입이다.

   
타입의 역할을 한다는 것은 인터페이스는 객체가 어떤 동작을 할 수 있는지를 정의한다는 것으로,
이것을 통해서 객체의 종류, 기능을 표현한다.
그리고 그 동작이 실제로 어떻게 구현될지는 구현 클래스에게 맡긴다.  

따라서, 인터페이스는 클래스가 어떤 동작을 할 수 있는지를 정의한다. 
  
```java
public interface Flyable {    // Flyable 인터페이스는 타입의 역할을 한다.
    void fly();               // 날 수 있다~
}  

publlic class Airplane implements Flyable {
    @Override
    public void fly() {
        System.out.println("Airplane is flying");
    }
}

public class Bird implements Flyable {
    @Override
    public void fly() {
        System.out.println("Bird is flying.");
    }
}

public class Main {
    public static void main(String[] args) {
        Flyable airplane = new Airplane(); // Flyable 타입으로 Airplane 객체를 참조
        Flyable bird = new Bird();

        airplane.fly();  // Airplane is flying.
        bird.fly();      // Bird is flying.
    }
}
```

## 상수 인터페이스?
static final 상수만 포함하고, 메서드는 없다.  
상수 인터페이스 방식은 초기에는 상수를 공유하려는 목적에서 사용되었다. 

```
interface Constants {
    static final int MAX_SPEED = 200;
}
```

하지만 위 코드는 상수 인터페이스 안티패턴으로 인터페이스를 잘못 사용했다.

1. 상수 인터페이스를 사용하면, 상수값을 외부 인터페이스로 노출한다. 
   그리고 이것을 다른 클래스들이 상속하면 내부 구현이 외부에 드러나게 된다.
2. 클래스가 어떤 상수 인터페이스를 사용하던 사용자에게는 아무런 의미가 없고 오히려 혼란을 주게된다.
   동시에 클라이언트 코드가 이 상수들에 종속되어 다음 릴리스에서 상수를 사용하지 않게 되더라도 여전히 상수 인터페이스를 구현해야 한다.



#### 상수 인터페이스의 목적이 상수를 공유하는 것인데, 왜 내부 구현이 외부에 노출되는 것을 걱정하는지?

**"상수 값을 외부 인터페이스로 노출한다"** 는 말은 상수값을 사용하려는 클래스가
해당 인터페이스를 불필요하게 상속받게 만들어 간접적으로 상수 값이 외부에 노출된다는 의미이다.
이 방식은 불필요한 상속을 강제하게 되어 설계에 문제가 발생할 수 있다.
상수를 공유하는 방법이 잘못된 방식으로 사용되었기 때문에 문제가 된다.

상수 인터페이스에서 상수를 정의하고 이를 다른 클래스들이 상속하게 되면, 상수 값 자체는 외부에 노출되지 않더라도, 
상속을 통해 그 인터페이스를 구현한 클래스는 인터페이스의 일부를 강제로 구현해야 한다.
따라서, 설계상 불필요한 상속 관계를 만들어내게 된다. 이렇게 상속 관계를 강제로 만들면 그 클래스는 이제 단순히 상수를 참조하는 것이 아닌, 상속을 받은 클래스가 되어 의도가 불분명해진다.
상수 인터페이스는 상수를 공유하려는 목적이었지만, 이를 상속받는 것이 불필요한 상속을 강제하게 되기 때문에, 상수만 사용하는 것이 아니라 인터페이스를 구현하는 클래스로서 외부에 노출되고,
상속이 그 클래스의 기능적 의미로 착각될 수 있다.  

상수 인터페이스는 상수 값만 사용하려는 의도를 불필요한 상속으로 변질시켜, 클래스를 과도하게 상속받게 만들고 설계를 복잡하게 한다. 
이로 인해 내부 구현이 외부에 노출되고, 상속의 의미가 왜곡되어 코드가 혼란스러워질 수 있다.

### 대안

하지만 불필요한 상속과 설계의 복잡성으로 이제는 public static final 필드나 **enum**을 사용하여 상수를 정의하는 것이 권장된다.


#### 상수 유틸리티 클래스
```java
public class ShapeConstants {
    public static final int CIRCLE = 1;
    public static final int SQUARE = 2;
    public static final int TRIANGLE = 3;
}
```

<br><br>  <br>  

정적 임포트를 하면 클래스 이름을 생략할 수 있다.
#### 정적 임포트
```java
import static effectivejava.ShapeConstants.*;

public class Main {
    String circle(){
        return CIRCLE;
    }
    ...   
}
```
