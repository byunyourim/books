## 불변 클래스?
불변 클래스란 인스턴스 내부 값을 수정할 수 없는 클래스로, String, BigInteger, BigDecimal 등이 불변 클래스로 정의된다.
가변 클래스보다 설계 및 구현이 쉬우며, 오류가 생길 여지가 적고 훨씬 안전하다.

<br><br>

**불변 객체**    
- 객체의 값이 한 번 설정되면 변경되지 않는다.

      
**가변 객체**    
- 생성 후에도 내부 데이터가 바뀔 수 있는 객체 
- StringBuilder 

     
**참조 변수**   
- 특정 객체를 가리키는 역할을 하며, 다른 객체를 가리키도록 변경할 수 있다.  




<br><br><br><br><br><br>

## 불변 클래스를 만들려면?
#### 객체의 상태를 변경하는 메서드를 제공하지 않는다.
  - setter 메서드와 같이 멤버 필드를 수정해서는 안된다.
#### 특정 클래스가 다른 클래스에 의해 상속될 수 없어야 한다.
  - 상속이 허용되면 하위 클래스가 부모 클래스의 동작을 변경하거나, 예상치 못한 방식으로 확장할 수 있다.
#### 모든 필드를 final로 선언한다.
  - 코드 작성자의 의도를 명확하게 드러냄
  - 새로 생성된 인스턴스를 동기화 없이 스레드로 건네도 문제없이 동작하도록 한다.
  - JLS, 17.5; Geotz06, 16
  - [docs.oracle.com](https://docs.oracle.com/javase/specs/jls/se8/html/jls-17.html)
#### 모든 필드를 private으로 선언한다.
  - 필드가 참조하는 가변 객체를 클라이언트에서 직접 접근하여 수정하는 일을 막는다.
  - 불변 객체가 되지만, 후에 내부 구현을 바꾸는데 제약이 생길 수 있다. 
#### 클래스 내부에서 사용하는 가변 객체의 참조가 외부에 노출되지 않도록 해야 한다.
  - 절대 클라이언트가 제공한 객체를 가리키게 해서는 안되며, 접근자 메서드가 그 필드를 그대로 반환해서도 안된다.
  - 외부에서 제공한 객체를 클래스 내부에서 그래도 사용하거나 반환하면 안된다
  - 방아적 복사를 수행해라

  ### 메모리의 가시성
  스레드는 자신의 로컬 메모리를 사용하는데, 이를 통해 다른 스레드가 사용하는 변수 값을 직접 읽기 못하고,
  값이 갱신되더라돋 다른 스레드에 그 값이 즉시 반영되지 않을 수 있다.
  이로 인해서 한 스레드에서 값을 변경했는데 다른 스레드에서 그 값이 바로 보이지 않는 문제가 밠생하는데
  이것을 메모리 가시성 문제라고 한다.  
     
  final 필드의 경우, JVM은 초기화 규칙을 적용해 한 스레드에서 초기화된 후 다른 스레드가 해당 값을 안전하게 읽을 
 수 있도록 한다.
  한 스레드에서 final 필드를 초기화하고, 그 객체를 다른 스레드로 전달할 때, final필드는 항상 초기화된 값으로 전달된다. 그래서 다른 스레드에서 값을 안전하게 읽을 수 있다. 따라서 동기화가 따로 필요없다.

<summary><mark><b>가변 객체의 반환과 수정</b></mark></summary>    
불변 객체는 외부에서 객체의 상태를 변경할 수 없기 때문에 getter나 setter를 통해 안전하게 반환하거나 설정할 수 있다.  
가변 객체는 상태가 변경될 수 있다. 따라서 getter나 setter를 사용하여 외부에 반환하거나 설정할 때 주의해야 함.  

String 객체 자체는 변경되지 않고, 새로운 객체를 참조한다. 
가변 객체는 객체 자체가 변경되고, 그 객체의 상태도 변경된다.

```java
public class MyClass {
    private List<String> list;

    public MyClass(List<String> list) {
        this.list = list;  // 외부 객체를 그대로 받아서 사용
    }

    // 접근자 메서드: 외부 객체를 그대로 반환
    public List<String> getList() {
        return list;  // 외부에서 수정 가능
    }
}
```

```java
List<String> externalList = new ArrayList<>();
externalList.add("item1");

MyClass myClass = new MyClass(externalList);
myClass.getList().add("item2");  // 외부에서 list 수정 -> MyClass 내부의 list 바뀜

System.out.println(externalList);  // ["item1", "item2"]
```
외부에서 getList()로 list를 가져와 수정했기 때문에, MyClass 내부의 list도 바뀌게 된다.
</details>

## 불변 클래스 특징
- 불변 객체는 단순하다. 
- 멀티스레드하여 동기화할 필요가 없다.
- 자유롭게 공유할 수 있다.
- 실패 원자성을 제공한다.
- 값이 다르면, 독립된 객체로 만들어야 한다.

불변 객체의 단점은 값이 다르면 반드시 독립된 객체로 만들어야 한다는 것이다. 값이 많아지면 비용이 많이 나간다.

원하는 객체를 완성하기까지의 단계가 많고, 중간 단계에서 만들어진 객체들이 모두 버려진다면 성능 문제가 더 불거진다. 

이에 대처하는 방법은 **다단계 연산**을 예측해 기본 기능으로 제공하는 것이다. 그러면 더 이상 각 단계마다 객체를 생성하지 않아도 된다.

## 불변 클래스를 만드는 방법
불변임으로 보장하려면 자신을 상속하지 못하게 해야 한다.
1. final 클래스로 선언하기
2. 모든 생성자를 private, package-private로 만들어 public 정적 팩터리를 제공하기.
```java
public class Complex {
  private final double re;
  private final double im;

  private Complex(double re, double im) {
    this.re = re;
    this.im = im;
  }

  public static Complex valueOf(double re, double im) {
    return new Complex(re, im);
  }
}
```

## 마무리
Getter가 있다고 해서 무조건 Setter를 만들지 말자.
모든 클래스를 불변으로 만들 수 없다. 하지만 가변 클래스더라도 변경할 수 있는 부분은 최소한으로 줄이자. (변경이 없게 만든 후 모두 final 선언을 하고, 특별한 이유가 없다면 모두 private final 선언을 하자.)

 

생성자는 불변식 설정이 모두 완료된 상태의 객체를 생성해야 한다. 즉, 확실한 이유가 없다면 생성자와 정적 팩터리 외에는 그 어떤 초기화 메서드도 public으로 제공해서는 안된다. 객체를 재사용할 목적으로 상태를 다시 초기화하는 메서드도 올바르지 않다.
