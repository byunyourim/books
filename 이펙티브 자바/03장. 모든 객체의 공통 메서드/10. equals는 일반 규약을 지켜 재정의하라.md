#### 1. 각 인스턴스가 본질적으로 고유한 경우

## equals 메서드 재정의 규약
동치 관게를 가져야 한다.
> 동치관계는 집합의 원소들을 같은 성질을 갖는 그룹으로 나누는 것이다.
> 예) 키가 같으면 같은 그룹~, 원소들이 서로 동치인지 기준으로 그룹을 만든 것을 동치 클래스라 한다. 


<br>

#### 반사성(reflexivity)
- null이 아닌 모든 참조 값 x에 대해, x.equals(x)는 true다.
- 객체는 자기 자신과 같아야 한다.

<br>

#### 대칭성(symmetry)
- null이 아닌 모든 참조 값 x, y에 대해, x.equals(y)가 true면 y.equals(x)도 true다.
```java
public final class CaseInsensitiveString{
    private final String s;

    public CaseInsensitiveString(String s){
        this.s = Objects.requireNonNull(s);
    }

    @Override public boolean equals(Object o){
        if(o instanceof CaseInsensitiveString)
            return s.equalsIgnoreCase(((CaseInsensitiveString) o).s);
        if(o instanceof String) // 한 방향으로만 동작한다.
            return s.equalsIgnoreCase((String) o);
        return false;
    }
}
```
```java
public static void main(String[] args) {
    CaseInsensitiveString2 cis = new CaseInsensitiveString2("Hello");
    String s = "hello";
    System.out.println(cis.equals(s)); // true (허용)
    System.out.println(s.equals(cis)); // false (String 클래스는 지원하지 않음)
  }
```

**why** String의 equals는 CaseInsensitiveString를 모른다!   
    
따라서 CaseInsensitiveString과 String을 비교할 때 한 방향에서는 같다고 하지만, 반대쪽에서는 다르다고 판단한다. CaseInsensitiveString끼리만 비교하도록 해야한다.  




<br>

#### 추이성(transitivity)
- null이 아닌 모든 참조 값 x, y, z에 대해, x.equals(y)가 true이고, y.equals(z)도 true면 x.equals(z)도 true다.
- 상위 클래스에 없는 새로운 필드를 하위 클래스에 추가하여 equals를 재정의할 때 발생


```java
public class Point {
	private final int x;
	private final int y;

	public Point(int x, int y) {
		this.x = x;
		this.y = y;
	}

	@Override public boolean equals(Object o) {
		if(!o instanceof Point)
			return false;
		Point p = (Point) o;
		return p.x == x && p.y == y;
	}
}
```

public class ColorPoint extends Point {

#### 해결1 : 상속 대신 컴포지션 사용

> **컴포지션**     
> 기존 클래스를 확장하는 대신, 새로운 클래스에 기존 클래스의 인스턴스를 포함시켜, 새로운 클래스가 기존 클래스의 기능을 메서드를 통해 재사용하는 방식이다.
   
   
- ColorPoint vs. ColorPoint: ColorPoint의 equals는 ColorPoint 객체끼리 비교할 때 color 값까지 비교.
- ColorPoint vs. Point: ColorPoint는 Point를 포함(컴포지션)하고, asPoint() 메서드를 통해 Point로 변환 후 Point의 equals를 사용하여 x, y만 비교.
- Point vs. Point: Point 객체끼리 equals를 사용해 x, y값을 비교.



즉, 상속을 사용하지 않고, 필요한 클래스 내에서 필드를 포함시켜서 관련 메서드로 처리하는 방식입니다.







<br>


#### 해결 2 : 추상 클래스의 하위 클래스 사용
추상 클래스의 하위 클래스에서는 equals 규약을 지키면서 값을 추가할 수 있다.   

상위 클래스의 인스턴스를 직접 만드는 게 불가능하기 때문에, 하위 클래스끼리의 비교가 가능하다.

#### 일관성(consistency)
- null이 아닌 모든 참조 값 x, y에 대해, x.equals(y)를 반복해서 호출하면 항상 true를 반환하거나 false를 반환한다.

## 양질의 equals 메서드 구현 방법
### 1. == 연산자를 사용해 입력이 자기 자신의 참조인지 확인함
- 자기 자신이면 true 반환
- 단순한 성능 최적화용으로, 비교 작업이 복잡한 상황일 때 유용

### 2. instanceof 연산자로 입력값 타입 확인
   
### 3. 입력값 -> 올바른 타입으로 형변환
2에서 타입 검사를 했으므로 예외가 발생하지 않음

### 4. 입력 객체와 자기 자신의 대응되는 '핵심' 필드들이 모두 일치하는지 하나씩 검사
모든 필드가 일치하면 true, 하나라도 다르다면 false를 반환

## AutoValue 프레임워크

AutoValue는 Java에서 불변 객체(immutable objects)를 쉽게 만들 수 있도록 도와주는 라이브러리로
객체의 모든 필드를 final로 선언하고, 생성자, getter 메서드, equals(), hashCode(), toString() 등을 자동으로 생성해준다.  

즉, Java에서 데이터를 담는 객체를 생성할 때 필요한 반복적인 코드를 자동으로 처리해주는 도구로, 클래스에 어노테이션 하나만 추가하면 AutoValue가 메서드를 알아서 작성해준다.
