#### 일반 규약
간결하면서 사람이 읽기 쉬운 형태의 유익한 정보를 반환해야 한다.
모든 하위 클래스에서 이 toString 메서드를 재정의해야 한다.  


toString을 잘 구현한 클래스는 사용하기 편하고, 디버깅이 쉽다.     

toString 메서드는 객체를 **println, printf, assert** 구문에 넘길 때, 혹은 디버거가 객체를 출력할 때 자동으로 호출된다.
 = 즉, 직접 호출하지 않더라도 다른 어딘가에서 쓰인다.    


 

- toString을 제대로 재정의하지 않는다면 쓸모없는 메시지만 로그에 남을 것이다.


<br><br><br><br><br><br>


## toString은 그 객체가 가진 주요 정보 모두를 반환하는 게 좋다.
```java
class Person {
    String name;
    int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    @Override
    public String toString() {
        return "Person{name='" + name + "', age=" + age + "}";
    }
}
```
설명할 수 있는 주요 정보를 문자열 형태로 반환해야 한다. 객체의 상태를 쉽게 이해할 수 있음

## 포맷 문서화
포맷을 명시하면, 해당 데이터를 쉽게 저장하거나 입출력할 수 있다.
예를 들어 CSV 파일처럼 사람이 읽을 수 있는 형태로 저장할 수 있고, 포맷에 맞는 문자열과 객체를 서로 변환할 수 있는 정적 팩터리 메서드나 생성자를 제공하는 것이 좋다.  
    
하지만 한 번 포맷을 명시하면, 나중에 포맷을 바꿀 때 호환성 문제가 생길 수 있. 포맷 변경 시 기존에 이 포맷을 사용하던 코드나 데이터가 엉망이 될 수 있다. 반대로, 포맷을 명시하지 않으면 나중에 데이터를 확장하거나 개선할 때 더 유연성을 가질 수 있다.


<br><br><br>  

추가로 포맷을 명시하려면 아주 정확하게 해야 한다

#### 반환 값의 정보를 API로 제공하자
포맷 여부와 상관없이 toString이 반환한 값에 포함된 정보를 얻어올 수 있는 API를 제공해야 한다.

예를 들어 PhoneNumber 클래스는 
필요한 정보인 지역 코드, 프리픽스, 가입자 번호용 접근자를 제공해야 한다. 
그렇지 않으면 프로그래머가 반환 값을 직접 파싱해야 한다.
```java
class PhoneNumber {
    private String areaCode;
    private String prefix;
    private String subscriberNumber;

    public String getAreaCode() {
        return areaCode;
    }

    public String getPrefix() {
        return prefix;
    }

    public String getSubscriberNumber() {
        return subscriberNumber;
    }
}
```
접근자(getAreaCode, getPrefix, getSubscriberNumber)를 통해, 값을 쉽게 사용할 수 있다.

##  toString 메서드를 재정의하지 않아도 되는 경우
- 정적 유틸리티 클래스의 경우, toString 을 제공할 이유가 없다.
  - Math나 Collections와 같은 클래스들은 인스턴스를 생성할 필요 없이 그 자체로 필요한 기능을 제공한다.
  - 이런 클래스는 toString 메서드를 제공할 필요가 없다.
- 열거 타입(Enums)은 이미 완벽한 toString을 제공하기 때문에 재정의하지 않아도 된다.
  - 기본적으로 toString()은 열거형의 이름을 반환하므로 특별히 변경할 필요가 없ek.

**그러나 하위 클래스들이 공유해야 할 문자열 표현이 있는 추상 클래스라면 toString을 재정의해야 한다.**
- 만약 추상 클래스가 있고, 여러 하위 클래스들이 공통적으로 사용할 toString 표현이 필요하다면, 추상 클래스에서 toString()을 재정의하여 각 하위 클래스에서 공통적으로 사용할 수 있도록 해야 한다.

#### AutoValue 프레임워크
AutoValue는 자바에서 자동으로 toString 메서드를 생성해주는 프레임워크이다.  

자동으로 생성된 toString은 클래스의 필드 값을 문자열로 잘 표현해주지만, 클래스의 '의미'까지는 파악하지 못한다.  


Person 클래스의 name, age 필드를 toString으로 자동 생성하면 "name=John, age=30"처럼 필드 값만 출력된다.
클래스의 의도나 역할을 나타내지 않기 때문에 **"이 클래스는 사람을 나타내는 클래스"**와 같은 의미는 담지 않는다.
    
그래고 Object의 toString보다는 유용함.

## 마무리
모든 구체 클래스에서 Object의 toString을 재정의하자.
상위 클래스에서 이미 알맞게 재정의한 경우는 예외다.
toString을 재정의한 클래스는 사용하기도 즐겁고 그 클래스를 사용한 시스템을 디버깅하기 쉽게 해준다.
toString은 해당 객체에 관한 명확하고 유용한 정보를 읽기 좋은 형태로 반환해야 한다.
