**"같은 버킷인데 왜 동치성 비교를 하지 않는지"**   
"같은 버킷"이라는 표현은 물리적으로 같은 해시 버킷 배열의 위치를 말한다.
하지만 두 엔트리가 같은 버킷에 있다고 해도, 실제로 equals()를 호출하는 조건은 아래와 같다
- get() 메서드가 조회 중인 키와 저장된 키의 hashCode() 값이 동일해야 한다.
- 만약 두 객체의 해시코드가 다르면, 같은 버킷에 저장된 엔트리라 해도 equals() 비교를 건너뛰고 다른 엔트리를 확인한다.

```java
if (first.hash == hash && ((k = first.key) == key || key != null && key.equals(k))) {
    return first;
}
```
- 첫 번째 조건: first.hash == hash
  - 현재 탐색 중인 노드의 해시코드(first.hash)와 찾는 키의 해시코드(hash)를 비교한다.
  - 해시코드가 다르면 두 번째 조건(equals)을 실행하지 않는다.
  - 즉, hash가 다르면 equals()는 호출되지 않는다.
- 두 번째 조건: ((k = first.key) == key || key != null && key.equals(k))
  - 첫 번째 조건을 만족할 때(해시코드가 같을 때)만 실행된다.
  - 키 객체(key)와 저장된 키(first.key)를 == 또는 equals()로 비교한다.

 <br>
 
```java
do {
    if (e.hash == hash && ((k = e.key) == key || key != null && key.equals(k))) {
        return e;
    }
} while ((e = e.next) != null);
```
- 같은 버킷 내에서 연결 리스트의 다음 노드들을 순회하며, 동일한 해시코드(e.hash == hash)를 가진 엔트리를 찾는다.
- 해시코드가 다르면 연결 리스트의 다음 노드로 넘어가며, equals()는 호출되지 않는다.
