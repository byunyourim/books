정적 메서드와 정적 필드만 담은 유틸리티 클래스는 객체 지향과 거리가 멀다. 생성자를 명시하지 않으면 기본 생성자가 자동으로 생성되기 때문에 의도치 않게 인스턴스화 될 수 있다.      

추상 클래스로 만들면 인스턴스를 만들 수 없지만, 상속 받아서 하위 클래스에서 인스턴스를 생성할 수 있다.  


<br><br><br>

## <mark>유틸리티 클래스?</mark>  
- java.lanag.Math
- java.util.Arrays
- java.util.Collections (특정 인터페이스를 구현하는 객체를 생성해주는 정적 메서드(혹은 팩터리) 모음)
- final 클래스와 관련한 메서드 모음
  final 클래스를 상속해서 하위 클래스의 메서드에 넣는 건 불가능하다.

유틸리티 클래스는 정적 메서드와 정적 필드만을 포함한 클래스로 **특정 기능을 수행하는 메서드를 제공하는 것**이 목적이기 때문에, 그 클래스의 인스턴스를 생성할 필요가 없다. 만약 인스턴스를 생성할 수 있도록 한다면, 잘못된 사용으로 인해 불필요한 객체가 생성될 수 있고, 코드의 명확성을 해칠 수 있다.
**하지만 생성자를 명시하지 않으면 컴파일러가 자동으로 기본 생성자를 만들어준다.**


<br><br><br>

## <mark>인스턴스화를 막으려면?</mark>
추상 클래스로 선언된 클래스는 인스턴스를 만들 수 없다. 
하지만 추상 클래스를 상속받아서 인스턴스를 생성할 수 있기 때문에, 추상 클래스로 만드는 것만으로는 완벽하게 인스턴스화를 방지할 수 없다. 또한 상속해서 사용하라는 뜻으로 사용자가 오해할 수 있다.  


- 컴파일러가 기본 생성자를 만드는 경우는 생성자를 명시하지 않은 경우이다.  
- 따라서, private 생성자를 추가하여 클래스의 인스턴스화를 막을 수 있다.
   
**인스턴스를 만들 수 없는 유틸리티 클래스**
```java
public class UtilityClass {
    // 기본생성자가 만들어지는 것을 막는다.(인스턴스 방지용)
    private UtilityClass() {
        // 생성자 내부 호출시 에러 던짐
        throw newe AssertionError();
    }
}
```
   
#### 1. 명시적 클래스를 private으로~
- 외부 : private으로 클래스의 외부에서 접근 불가   
- 내부 : 에러를 던져 실수로 생성자를 호출하지 않도록 한다.(주석추가하여 보다 직관적으로~)
#### 2. 상속 불가능
- 모든 생성자는 명시적이든 묵시적이든 상위 클래스의 생성자를 호출하는데, private로 선언하여서 하위클래스가 상위 클래스에 접근할 수 없다.
