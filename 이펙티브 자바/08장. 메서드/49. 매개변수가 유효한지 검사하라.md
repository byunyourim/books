메서드와 생성자 대부분은 입력 매개변수 값이 특정 조건을 만족해야 함.

**매개변수의 제약은 반드시 문서화해야 하고, 메서드 바디가 시작되기 전에 검사해야 한다.**
  
-> 메서드 시작 부분에서 매개변수를 확인하고 잘못된 값이 넘어온 경우 예외를 던지도록 코드를 작성하자.



### 문서화
넘어온 매개변수가 제약 조건을 어길 경우 예외를 던져 처리할 수 있다. 
만약 public, protected 메서드가 예외를 던진다면 문서화해야 한다.

주석에서 @throws를 사용하자. 
제약을 어긴 경우 발생하는 예외도 함께 기술하자.  



모든 메서드에 적용되는 사항이 있다면 클래스 수준의 주석에 적는 것이 좋다.

---

```java
/*
* (현재 값 mod m) 값을 반환한다. 이 메서드는
* 항상 음이 아닌 BigInteger를 반환한다는 점에서 remainder 메서드와 다르다.
*
* @param m계수(양수여야 한다.)
* @return 현재 값 mod m
* @throws ArithmeticException m이 0보다 작거나 같으면 발생한다.
*/
public BigInteger mod(BigInteger m) {
	if (m.signum() <= 0)
		throw new ArithmeticException("계수(m)은 양수어야 합니다. " + m);
	... // 계산 수행
}
```



default, private 메서드는 호출될 수 있는 범위가 제한되기 때문에, 개발자가 이러한 메서드에 전달되는 인자를 더 잘 통제할 수 있다. 

private, default 메서드는 해당 클래스 내에서만 호출된다. 호출되는 상황을 개발자가 완전하게 제어할 수 있다. 
따라서 유효한 값이 전달될 것을 보장할 수 있다. 그리고 예외 발생 가능성이 있는 부분도 내부 검증을 통해 처리할 수 있다.
