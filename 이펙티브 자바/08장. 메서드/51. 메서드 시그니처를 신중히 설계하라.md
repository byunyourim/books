## API 설계요령
#### 1. 메서드 이름을 신중히 짓자.
#### 2. 편의 메서드를 너무 많이 만들지 말자.
#### 3. 매개변수 목록은 짧게 유지하자. (4개 이하)
같은 타입의 매개변수가 여러 개 나오는 것 지양하자.

##### 매개변수 목록 줄이는 기술 3가지
1. 여러 메서드로 쪼갠다. (List 인터페이스)

어떤 리스트에서 주어진 원소를 찾아야 할 때, 지정된 범위의 부분 리스트에서 주어진 원소를 찾아야 한다면  

```java
findElementOfSubList(int fromIndexOfSub, int toIndexOfSub, Object o);
```
아래와 같이 쪼개자.
```java
List<E> subList(int fromIndex, int toIndex);

int indexOf(Object o);
```
- 부분 리스트를 구하는 기능 + 주어진 원소를 찾는 기능


2. 매개변수 여러 개를 묶어주는 도우미 클래스를 만든다.
매개변수가 많다면 매개변수를 묶어줄 수 있는 클래스를 만들어서 하나의 객체로 전달할 수 있다.

- 연관된 데이터를 함께 다루자.
- 
- 카드게임을 클래스로 만들어보자.
```java
class Card {
    private final Rank rank;
    private final Suit suit;

    public Card(Rank rank, Suit suit) {
        this.rank = rank;
        this.suit = suit;
    }

    static class Rank {
        private final int value;

        // 생성자, get메서드 생략
    }

    static class Suit {
        private final String name;

        // 생성자, get메서드 생략
    }
}

```

4. 객체 생성에 사용한 빌더 패턴을 메서드 호출에 응용하라.

#### 4. 매개변수의 타입으로는 클래스보다는 인터페이스가 낫다
HashMap 대신 인터페이스인 Map을 사용하면 
TreeMap, ConcurrentHashMap, TreeMap 등 어떤 Map 구현체라도 인수로 건넬 수 있다. 

#### 5. boolean보다는 원소 2개짜리 열거 타입이 낫닫. 
열거 타입(enum)을 사용하면 코드를 읽고, 쓰기가 더 쉽다.

```java
public enum TemperatureScale { FAHRENHEIT, CELSIUS }
```

```java
// Thermometer.newInstance(true)

// 더 명확함
Thermometer.newInstance(TemperatureScale.FAHRENHEIT);
```
