try-catch 블럭 안에서는 jvm이 수행하는 최적화가 제한된다.


JVM은 코드 실행 중 성능을 높이기 위해 다양한 최적화(Optimization)를 수행한다.
- 루프 언롤링: 반복문을 여러 번 실행하지 않고, 반복 횟수를 줄이거나 펼쳐서 실행 속도를 높임.
- 인라인화: 자주 호출되는 메서드의 코드를 호출 대신 직접 삽입.
- 중복 제거: 동일한 연산을 반복하지 않도록 계산 결과를 재사용.



<br>

하지만, try-catch 블록이 있으면, JVM은 예외 발생 가능성 때문에 최적화를 제한한다.

- 예외 발생 시점과 예외 처리를 추적해야 하므로 최적화의 자유도가 줄어든다.
예외가 발생하지 않을 것이라고 가정하고 최적화할 수 없기 때문에 코드 실행이 느려짐.

- 예외 처리로 인한 추가 오버헤드
예외 객체를 생성하고 스택 트레이스를 캡처하는 등의 작업이 발생

### 옵셔널(Optional) 또는 특정 값을 사용하는 이유

Optional 자체는 불변 객체로 설계됨. 따라서 Optional에 포함된 값은 변경할 수 없고,
상태를 변경하려면 새로운 Optional 객체를 생성해야 한다.

따라서 값의 불변성을 보장할 수 있어, 동시성 문제와 상태 간섭 문제를 예방합니다.
